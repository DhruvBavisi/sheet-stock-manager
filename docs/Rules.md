# Rules — StockLog

> Boundaries for anyone (human or AI) writing code in this repo: which libraries to use or avoid,
> how to handle errors, and what not to touch. Read this before making changes.
> Last updated: 2026-08-27.

---

## 1. Golden rules (read first)

1. **Never call Google Sheets / Apps Script directly from the browser.** All sheet writes go
   through the same-origin server route `/api/sheets`. The client calls `appendRow()`, which posts
   to our own server; the server fans out to Google. (Avoids CORS, keeps URLs off the client.)
2. **Never commit secrets.** Apps Script URLs and Sheet IDs are sensitive. They belong in `.env`
   (`VITE_*`) or the in-app Settings dialog (`localStorage`) — **never** hard-coded in source and
   **never** committed. Confirm `.env` is git-ignored before adding one.
3. **Never edit `src/routeTree.gen.ts`.** It is auto-generated by the TanStack Router plugin.
   Change routes by adding/editing files in `src/routes/`, then let it regenerate.
4. **All colors use `oklch`.** `src/styles.css` mandates it. Do not add hex/rgb/hsl color values
   to the theme tokens. (See [`Design.md`](./Design.md).)
5. **Keep the domain model in `src/lib/stocklog.ts`.** Task/sheet types (`TaskType`, `MachineSheet`,
   `SheetType`, `AppConfig`, `LogEntry`, `AppendRowPayload`), sheet definitions (`TASKS`,
   `MACHINE_SHEETS`, `SHEETS`), materials, and persistence live there — not scattered across
   components. Adding a task or sheet shape means editing this file **and** `APPS_SCRIPT_CODE`
   (kept in sync with [`docs/apps-script.gs`](./apps-script.gs)) together.

## 2. Libraries — use these

The stack is already chosen. Prefer what's installed over adding anything new.

- **UI:** shadcn/ui components in `src/components/ui/` (built on **Radix UI**). Compose these; don't
  hand-roll dialogs, selects, popovers, etc.
- **Class names:** the `cn()` helper (`src/lib/utils.ts`, clsx + tailwind-merge). Use it for every
  conditional/merged className.
- **Styling:** Tailwind CSS **v4** utilities + the semantic tokens in `styles.css`
  (`bg-background`, `text-foreground`, `bg-primary`, `border-input`, …).
- **Icons:** `lucide-react`.
- **Toasts:** `sonner` (the `<Toaster/>` is already mounted in `__root.tsx`). Use `toast.success` /
  `toast.error` for user feedback.
- **Routing:** TanStack React Router (file-based). **Data/server state:** TanStack React Query
  (the `QueryClient` is already provided).
- **Dates:** `date-fns` is available; simple formatting helpers (`todayISO`,
  `formatDateDDMMMYYYY`) already exist in `stocklog.ts` — reuse them.
- **Forms/validation:** `react-hook-form` + `zod` + `@hookform/resolvers` are installed. If you add
  a new form, prefer them; the existing main form uses controlled `useState` (leave it unless
  refactoring deliberately).

## 3. Libraries — avoid

- ❌ **No other UI kit** (MUI, Chakra, Ant, Bootstrap). shadcn/ui + Radix only.
- ❌ **No other styling system** (styled-components, emotion, CSS Modules, plain global CSS files).
  Tailwind v4 + the token file only.
- ❌ **No other router / meta-framework conventions.** No Next.js, no Remix, no `src/pages/`,
  no `getServerSideProps`. This is TanStack Start file-based routing.
- ❌ **No other global state library** (Redux, Zustand, Jotai, MobX) unless there's a real need —
  local state + React Query cover current requirements.
- ❌ **No direct `fetch` to `script.google.com` from client code.** Go through `/api/sheets`.
- ❌ **No new HTTP client** (axios, ky) — the native `fetch` used throughout is sufficient.
- ❌ Don't add a heavy date/lodash dependency for something small — write a helper.

## 4. Error-handling rules

Follow the patterns already in the codebase:

- **User-facing errors → toasts.** Validation and sync failures surface via `sonner`
  (`toast.error(message)`), never a thrown-uncaught exception in the UI.
- **Server route returns structured JSON**, never a bare 500 stack:
  - `400` — missing endpoints or payload.
  - `502` — partial or total sync failure; include `syncedCount`, `totalEndpoints`, `errors[]`.
  - `200` — all endpoints synced.
- **Tolerate partial failure.** Multi-endpoint sync uses `Promise.allSettled` — one account failing
  must not abort the other. Report "synced to N of M".
- **Retry transient failures** with the existing `retry(task, attempts = 2)` helper (250ms×attempt
  backoff) before giving up on an endpoint.
- **Detect Google login/HTML responses.** If Apps Script returns HTML instead of JSON, throw a
  message that tells the user to redeploy as *"Execute as: Me"* / *"Anyone"* — don't swallow it.
- **Never lose the entry.** Every submit is written to the local log regardless of sync result, with
  its `synced` / `syncedCount` recorded.
- **SSR errors** are normalized in `server.ts` (h3-swallowed 500s → HTML page) and caught by the
  route `errorComponent` / `notFoundComponent` in `__root.tsx`. Don't remove that plumbing.

## 5. Coding conventions

- **TypeScript, typed.** No `any` where a real type exists; reuse the types in `stocklog.ts`.
- **Functional components + hooks.** Custom hooks live in `src/hooks/`.
- **Path alias `@` → `/src`** for imports (`import { cn } from "@/lib/utils"`).
- **SSR-safe.** Guard browser-only APIs (`window`, `localStorage`, `navigator`) with
  `typeof window === "undefined"` checks, as `stocklog.ts` does.
- **Format & lint before committing:** `npm run format` (Prettier) and `npm run lint` (ESLint 9)
  must pass.
- **Match the surrounding style** — semantic Tailwind tokens, `rounded-xl`/`rounded-2xl`, existing
  spacing rhythm.

---

## 6. Security & data rules

- **Secrets:** never commit `.env`, Apps Script URLs, or Sheet IDs. Treat them as credentials.
- **CSRF:** the `csrfMiddleware` (filtered to `serverFn` handlers) in `start.ts` stays enabled.
- **Apps Script deployment:** the web app must be *"Execute as: Me"* + *"Who has access: Anyone"*
  for anonymous server-side POSTs. Document this for users; don't work around it insecurely.
- **Local storage limits:** the log is capped at 100 entries (`saveLog` slices). Keep that cap.
- **Config in `localStorage` is plaintext** on the device — acceptable for this app's threat model,
  but don't store anything more sensitive there.

## 7. Routing rules (from `src/routes/README.md`)

- Every `.tsx` in `src/routes/` **is** a route. Only `__root.tsx` is the root layout.
- Dynamic: `$id`. Optional: `{-$category}`. Splat: `$.tsx` (read via `_splat`).
- Server routes use `createFileRoute(...).server.handlers` (see `api/sheets.ts`).
- Don't create `src/pages/` or other frameworks' folder conventions.

## 8. Quick do / don't

| ✅ Do | ❌ Don't |
|------|---------|
| Reuse `stocklog.ts` types & helpers | Redefine `LogEntry`/`AppConfig` elsewhere |
| Add sheet writes via `/api/sheets` | `fetch` Google directly from the client |
| Use shadcn/ui + `cn()` | Add MUI/Chakra or styled-components |
| Use `oklch` tokens | Add hex/rgb colors to the theme |
| Add routes as files in `src/routes/` | Edit `routeTree.gen.ts` or add `src/pages/` |
| Toast user errors, return structured server errors | Throw raw errors to the UI or return bare 500s |
| Keep `.env` out of git | Commit script URLs / sheet IDs |
